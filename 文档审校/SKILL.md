# 文档审校

## 名称

文档审校（`doc-proofread`）

## 说明

对给定文字做**只读**审校，输出问题清单。不改写、不润色、不推测作者意图，只报告能定位到原文的问题。

检查四类问题：

| 类别 | 判据 |
|---|---|
| 错别字 | 别字、多字漏字、术语/专名写法前后不一致、同音词误用（如「申明 / 声明」） |
| 时间矛盾 | 完成早于启动；日期、期限、时序前后冲突；「当日 / 逾期」等相对时间与绝对日期对不上 |
| 数字口径 | 同一指标前后数值、单位、数量级不一致；「约 / 累计 / 合计」与分项不符；百分比与基数不匹配 |
| 缺失条件 | 规则句缺前提、主体、时限、起算点、例外或责任方，导致无法执行 |

**输出上限：每次最多 5 项。** 按严重度排序：时间矛盾 / 数字口径 > 缺失条件 > 错别字。超过 5 条只列前 5 条，并注明还有几项未列。无原文依据的猜测不列入。

## 触发条件

命中任一即启用：

- 用户说「审校 / 校对 / 挑错 / 检查错别字 / 核一下 / 看看有没有问题」。
- 用户粘贴文本并要求核对时间、数字，或检查条件是否齐全。
- 交付文档、规则、公告、清单前的最后一遍检查。

不启用：要求改写润色、扩写、翻译、生成新文档、直接修改原文。

## 步骤

1. 取待审文字；用户未给文字时，用下方「演示文字」跑一遍自测，并明确说明这是演示、非用户文档结论。
2. 逐句标注四类问题候选，记录**原文片段**和句序号。
3. 交叉核对：
   - 把所有日期排成时间线，查先后倒置；
   - 把同一指标的数字（含单位、量级、约数）并列比较；
   - 对「即 / 逾期 / 默认 / 无需 / 按…处理」等触发词，检查前提、主体、时限、例外是否齐全。
4. 去重筛选：一处只记一类主问题；剔除无依据的猜测；按严重度排序，保留前 5 项。
5. 按输出格式给清单；四类均无问题时输出「未发现四类问题」。全程只读，不动原文。

## 输出格式

最多 5 行，每行：

`[类别] 句N「原文片段」→ 问题；需核实项`

结尾一行：`共 N 项（上限 5）`；有未列项时追加 `另有 M 项未列`。

## 演示文字（内置 2 句）

> 1. 项目于 2024 年 3 月立项，要求 2023 年 12 月前结项，预算 50 万元，实际支出约 5 万元。
> 2. 申请人提交申明材料后即于当日生效，逾期未复核的按默认通过处理，无需另行通知。

演示审校结果（示例输出）：

```text
[时间矛盾] 句1「2024 年 3 月立项 … 2023 年 12 月前结项」→ 结项早于立项 3 个月；核实两个日期。
[数字口径] 句1「预算 50 万元 / 实际支出约 5 万元」→ 数量级差 10 倍；核实是否漏写 0 或属不同口径。
[错别字] 句2「申明材料」→ 应为「声明材料」。
[缺失条件] 句2「逾期未复核」→ 未定义逾期天数与起算点；核实时限。
[缺失条件] 句2「按默认通过处理」→ 缺适用前提、复核主体与例外情形。
共 5 项（上限 5）
```

## 边界

- 只读：不改写、不替用户判定事实真伪，只指出需核实处。
- 不查外部资料；日期与数字以原文内部一致性为准。
- 本文件为交付草案，**未安装**到任何 skills 目录，不会被自动加载。
